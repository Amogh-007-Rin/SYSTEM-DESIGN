# Module 09 — Further Reading

- **"The Google File System" (Ghemawat, Gobioff, Leung — SOSP 2003)** — the original GFS paper. Short, readable, and the direct ancestor of HDFS's design; essential for understanding why large chunks, a single master, and replication-as-the-default were the right calls for Google's workload at the time.
- **Apache Hadoop HDFS Architecture Guide** (hadoop.apache.org, HDFS Architecture documentation) — the official documentation for HDFS's NameNode/DataNode design, including HDFS High Availability (standby NameNode) and Federation, which directly address the single-master limitations discussed in this module's Design Challenge 02.
- **AWS — "Amazon S3 Strong Consistency"** (aws.amazon.com/s3, and the associated AWS News Blog post from December 2020 announcing strong read-after-write consistency for all S3 operations) — the primary source for S3's actual consistency model, superseding the older "eventually consistent" framing that's still useful for understanding object storage in general.
- **AWS — "Amazon S3 Storage Classes" documentation** (aws.amazon.com/s3/storage-classes) — the official reference for S3 Standard, Standard-IA, Glacier, and Glacier Deep Archive, useful for grounding the hot/warm/cold tiering discussion in this module's deep dive against real, current pricing/retrieval tiers.
- **"The Log-Structured Merge-Tree (LSM-Tree)" (O'Neil, Cheng, Gawlick, O'Neil — Acta Informatica, 1996)** — the original academic paper introducing the LSM tree, for readers who want the formal treatment behind the memtable/SSTable/compaction model covered in this module's deep dive.
- **RocksDB Wiki — "RocksDB Overview" and "Compaction"** (github.com/facebook/rocksdb/wiki) — Facebook's production-grade LSM-tree storage engine, with detailed, practitioner-oriented documentation on compaction strategies (leveled vs. universal) that goes well beyond the simplified single-pass compaction in this module's example.
- **Apache Cassandra Documentation — "Storage Engine"** (cassandra.apache.org/doc, Architecture section) — Cassandra's own description of its LSM-tree-based storage engine, useful as a second real-world implementation to compare against RocksDB's.
- **PostgreSQL Documentation — "Indexes" and "B-Tree Indexes"** (postgresql.org/docs, Indexes chapter) — the canonical reference for how a production B-tree-backed relational database actually implements and uses its default index type, complementing this module's higher-level LSM-vs-B-tree comparison.
