# Module 04 — Databases

> Almost every hard system design decision eventually traces back to a database decision — how it's indexed, how it's replicated, how it's split. This module is the longest in the repository for a reason.

---

## Prerequisites

| Module | Topics Needed |
|---|---|
| [Module 01 — Foundations](../module-01-foundations/) | Consistency, durability, and trade-off vocabulary |

> 💡 Complete prerequisite modules first — this one builds directly on them.

---

## What You'll Learn

By the end of this module you will be able to:
- Explain ACID properties and apply them to real transaction design
- Choose between SQL and NoSQL (and between NoSQL types) using real trade-offs, not slogans
- Explain how B-tree indexes work and why they speed up some queries and not others
- Design a replication and sharding strategy for a dataset that no longer fits one machine
- Implement consistent hashing, the algorithm underlying most distributed sharding schemes
