# Module 19 — Further Reading

- **"Hidden Technical Debt in Machine Learning Systems"** (Sculley, Holt, Golovin, Davydov, Phillips, Ebner, Chaudhary, Young, Crespo, Dennison — Google, NeurIPS 2015) — the foundational paper on why ML systems accumulate a distinct kind of technical debt that doesn't show up in code review: entanglement between features, undeclared consumers of a model's output, feedback loops, and data dependencies that are far harder to detect than code dependencies. Essential background for this module's entire premise that ML systems fail differently than traditional software.
- **Uber Engineering Blog — "Michelangelo: Uber's Machine Learning Platform"** (eng.uber.com) — Uber's widely-cited engineering writeup on building one of the first large-scale internal feature stores and ML platforms, covering the online/offline feature store split and the training-serving skew problem this module's concepts section is built around, from the team that helped popularize the "feature store" term industry-wide.
- **FAISS — Facebook AI Research / Meta Engineering** (the FAISS GitHub repository and wiki, github.com/facebookresearch/faiss, plus the associated paper "Billion-scale similarity search with GPUs" by Johnson, Douze, Jégou) — the primary source and library documentation for the IVF and product-quantization approximate nearest neighbor techniques covered in the deep dive.
- **"Efficient and Robust Approximate Nearest Neighbor Search Using Hierarchical Navigable Small World Graphs"** (Malkov, Yashunin — IEEE TPAMI, 2018) — the original HNSW paper, for readers who want the formal graph-based algorithm behind the HNSW index type referenced throughout the deep dive and recommendation/RAG sections.
- **"Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"** (Lewis, Perez, Piktus, Petroni, Karpukhin, Goyal, Küttler, Lewis, Yih, Rocktäschel, Riedel, Kiela — Facebook AI Research, NeurIPS 2020) — the original RAG paper that introduced and named the retrieval-augmented generation architecture this module's RAG section and Design Challenge 02 are built around.
- **Pinecone — "What is a Vector Database?" and Pinecone Learning Center** (pinecone.io/learn) — a widely-read, practitioner-oriented engineering explainer series covering vector database fundamentals, chunking strategy trade-offs, and embedding pipeline design, written by one of the leading managed vector database providers referenced in this module's RAG coverage.
- **Weaviate Documentation — "Concepts: Vector Indexing"** (weaviate.io/developers/weaviate) — Weaviate's own documentation on HNSW-based indexing and hybrid (vector + keyword) search, useful as a second real-world vector database implementation to compare against Pinecone and pgvector.
- **PostgreSQL pgvector — Official Repository** (github.com/pgvector/pgvector) — the official pgvector extension repository and README, documenting how PostgreSQL adds vector similarity search (including HNSW and IVFFlat index types) directly inside an existing relational database, the basis for this module's "extend vs. buy vs. build" vector database trade-off discussion.
