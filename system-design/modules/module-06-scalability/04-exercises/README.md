# Module 06 — Exercises

## Design Challenges

| Challenge | Description |
|---|---|
| [01 — Scaling a Monolith from 100 to 1M Users](./design-challenges/challenge-01.md) | Evolve a single-server design through 5 stages of scale, naming the bottleneck and fix at each stage |
| [02 — Scalable Image Upload and Processing Pipeline](./design-challenges/challenge-02.md) | Design a pipeline that accepts image uploads and processes them (resizing, thumbnails) at scale |

> 💡 **Note:** This module has no coding challenges — scalability is primarily an architectural discipline best practiced through design exercises rather than data-structure implementation. The hands-on coding in this module lives in [`01-concepts/examples/`](../01-concepts/examples/) and [`02-deep-dive/examples/`](../02-deep-dive/examples/), which simulate Amdahl's Law, Little's Law, and a reactive auto-scaling policy directly.

Both design challenges have full worked solutions — attempt each one yourself first before reading the solution, since the value of a design challenge is in the struggle of identifying the bottleneck yourself, not in reading someone else's answer.
