# Module 20 — Further Reading

- **"Announcing Snowflake" — Twitter Engineering Blog (2010)** — the original post introducing Twitter's Snowflake distributed ID generation service, the direct inspiration for this module's [`snowflake-id-generator.ts`](../01-concepts/examples/snowflake-id-generator.ts) example and the motivation for the bit-layout (timestamp + machine ID + sequence) used throughout this module's ID generation discussion.
- **AWS Builders' Library — "Workload isolation using shuffle-sharding"** — Amazon's own writeup of the shuffle-sharding technique referenced in this module's [cell-based architecture deep dive](../02-deep-dive/README.md#cell-based-architecture), including the Route 53 case study of using it to contain blast radius across customers sharing infrastructure.
- **AWS Builders' Library — "Avoiding fallback in distributed systems" and "Timeouts, retries, and backoff with jitter"** — AWS's own analysis of retry storms and why full jitter outperforms plain exponential backoff, directly underlying the reasoning in this module's [backoff and retry section](../01-concepts/README.md#backoff-and-retry-strategies) and the [`exponential-backoff-jitter.ts`](../01-concepts/examples/exponential-backoff-jitter.ts) example.
- **Slack Engineering Blog — posts on incident response and infrastructure resilience** — Slack has written publicly about isolating blast radius and operating resiliently at scale, the same motivation behind this module's [cell-based architecture and bulkhead coverage](../02-deep-dive/README.md).
- **Martin Fowler — "BlueGreenDeployment"** (martinfowler.com/bliki/BlueGreenDeployment.html) — the canonical short writeup defining blue-green deployment, referenced in this module's [designing-for-operability section](../02-deep-dive/README.md#designing-for-operability).
- **Martin Fowler — "FeatureToggle"** (martinfowler.com/articles/feature-toggles.html) — a thorough treatment of feature flag categories and implementation patterns, extending this module's [canary deployments and feature flags coverage](../02-deep-dive/README.md#canary-deployments-and-feature-flags).
- **Google — Site Reliability Engineering (the SRE book), Chapter 8: "Release Engineering"** (sre.google/sre-book/release-engineering/, free to read online) — Google's own account of how release engineering, gradual rollout, and rollback safety are treated as a discipline at scale, directly relevant to this module's progressive delivery and operability material.
- **Redis documentation — "EVAL", "Scripting with Lua"** (redis.io/docs/manual/programmability/eval-intro/) — the authoritative reference for how Redis's Lua scripting guarantees atomicity, the exact mechanism underlying the distributed rate limiter's Lua script in [`03-interview-prep/sample-answer.md`](../03-interview-prep/sample-answer.md).
