# Design Challenge 02: A RAG-Based Document Q&A System

**Difficulty:** Hard

## Prompt

Design a Retrieval-Augmented Generation (RAG) system that lets users ask natural-language questions over a large internal document set (e.g., company policy documents, technical documentation, support articles) and get accurate, grounded answers generated by an LLM.

## What to Produce

1. **Separate the two pipelines.** Describe the offline ingestion pipeline and the online query pipeline as distinct systems with distinct latency/throughput requirements, and explain why conflating them would be a design mistake.
2. **Chunking strategy.** Describe how source documents are split into chunks, what chunk size and overlap trade-off you'd choose, and why.
3. **Embedding pipeline.** Describe what runs the embedding model, when, and how re-embedding is handled when a source document is updated or deleted.
4. **Vector database choice.** Pick one of Pinecone, Weaviate, or pgvector (or justify a different choice) and explain why, given the company's likely existing infrastructure and scale.
5. **Retrieval and generation.** Describe the online query path end to end: question in, answer out — including what happens if retrieval returns irrelevant or no good matches.
6. **Address a failure mode.** What happens when the LLM hallucinates despite being given retrieved context, or when retrieval returns stale information from a document that's since been updated? Propose at least one concrete mitigation for each.
7. At least 2 explicit trade-offs.

A full worked solution is in [`challenge-02-solution.md`](./challenge-02-solution.md). The retrieval mechanism itself is demonstrated hands-on in [`02-deep-dive/examples/ann-search.ts`](../../02-deep-dive/examples/ann-search.ts).
